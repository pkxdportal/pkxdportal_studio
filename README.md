# PK XD PORTAL — объединённый сайт

В одном проекте сохранены четыре раздела:
- Посты и новости, включая поиск, категории, закреплённые публикации и отдельные страницы постов.
- Студия правил.
- Конструктор сундуков.
- Редактор аватарок.

## Структура
- `index.html` — главная страница со всеми четырьмя разделами и лентой постов.
- `studio.html` — три редактора из первого сайта. Прямые ссылки: `studio.html#rules`, `studio.html#chests`, `studio.html#avatars`.
- `posts/` — отдельные HTML-страницы постов.
- `posts.json` — данные ленты.
- `assets/` — изображения для постов и дизайна.
- `style.css` — стиль главной страницы и ленты.
- `src/index.js`, `wrangler.jsonc` — исходный Cloudflare Worker авторизации из второго сайта.

## Публикация
Это статический сайт. Загружай все файлы и папки ZIP в корень репозитория `pkxdportal/pkxdportal_studio` для GitHub Pages.
Сохраняй относительные пути и папки. При размещении по текущему адресу `https://pkxdportal.github.io/pkxdportal_studio/` структура изображений и публикаций сохраняется.


## Локальный просмотр
Используй локальный HTTP-сервер, иначе браузер может блокировать загрузку `posts.json` при открытии `file://`.

```bash
python -m http.server 8000
```

Открой `http://localhost:8000/`.

## Ограничение
Кнопка «Нравится» на страницах постов использует `localStorage` браузера. Это локальный счётчик, а не общая серверная статистика. Так было и в исходном сайте.

## Доступ для команды без GitHub
- Открыть главную страницу сайта, нажать «Вход для владельцев».
- Ввести командный пароль, после чего появятся три редактора: правила, сундуки, аватарки.
- Редакторы открываются напрямую по ссылкам studio-app.html#rules, #chests, #avatars. Никакой GitHub OAuth не нужен.
- Кнопка «Выйти из редакторов» скрывает инструменты на устройстве.
- При прямом открытии studio.html также доступен парольный вход.
- Публикации читаются всеми. Для владельцев предусмотрен posts-admin.html с локальными черновиками и публикацией через Cloudflare Worker после настройки сервера.
- Пароль расположен в публичном JavaScript. Это удобный фильтр интерфейса, а не серверная защита.

## Парольная публикация с Cloudflare Worker
Новый фронтенд posts-admin.html умеет создавать и изменять публикации, сохранять локальные черновики и отправлять изменения в Cloudflare Worker.
Для записи на общий сайт нужно однократно подключить сервер, иначе кнопка «Опубликовать» сохранит только черновик.
Рабочий Worker: исходник src/index.js. В Cloudflare Worker pkxd-auth добавить secrets:
- POST_EDITOR_PASSWORD: тот же пароль, который используется для входа в редакторы.
- GITHUB_WRITE_TOKEN: fine-grained token GitHub только для pkxdportal/pkxdportal_studio с правом Contents: Read and write.
После этого выполнить deploy обновлённого Worker: npx wrangler deploy. Нельзя публиковать токен в wrangler.jsonc, JS, README или GitHub.
Health endpoint GET /api/health возвращает ready:true только если оба секрета существуют.
Сервер выполняет запись в GitHub API. Владельцы сайта используют пароль, GitHub аккаунт им не нужен.
Пароль приложения на статическом сайте проверяется SHA-256, поэтому не отображается открытым текстом в editor-access.js. Проверка в браузере не является серверной защитой. Для публикаций Worker дополнительно сверяет POST_EDITOR_PASSWORD на сервере.

Навигация: index.html — единственная главная страница. studio-app.html — компактная панель и iframe движка studio-engine.html. Кнопки «На главную» и старое внутреннее переключение возвращают на index.html. В правилах отключено патологическое сжатие шрифта пунктов, но сохранён автоподбор для пояснений.
